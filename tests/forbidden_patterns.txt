# forbidden_patterns.txt — strings that must never appear in a tracked file.
#
# This kit is developed by dogfooding: the author's live work loop lives inside
# a clone of it. The allowlist .gitignore keeps his DATA out of the repo; this
# file keeps his identifiers out of the KIT — paths, notification topics,
# channel ids, client names, personal addresses that leak in via a copy-paste
# from a working session.
#
# FORMAT: one POSIX ERE per line ("#" = comment, blank lines ignored).
# Each pattern is a plain literal with ONE bracket expression in it — the
# bracket matches the bare character(s) inside it, so the pattern matches the
# forbidden string while the pattern's own text does not (the "[" breaks the
# adjacency the regex requires). THIS FILE therefore passes its own scan and
# needs no exemption (an exempted file is a hole, and a hole in a guard is how
# the guard dies).
#
# Corollary: a ONE-CHARACTER forbidden word cannot be written this way — there
# is no adjacency to break, so "[X]" would match its own line. Write the
# collocations instead: put the word first and a bracket class of the
# characters that follow it in real prose (see the in-group vocabulary below).
#
# tests/test_c_privacy.sh derives a positive sample from every line by
# deleting the [ ] and \ characters, and asserts each one is caught — so a
# pattern that stops matching what it is named for turns the suite red.
#
# NOT forbidden, on purpose: "yohey-w" — the author's GitHub handle. It is
# load-bearing in the clone URLs and the LICENSE, and it is public by
# construction. Patterns below must never match it.
# ═══════════════════════════════════════════════════════════════════════════
