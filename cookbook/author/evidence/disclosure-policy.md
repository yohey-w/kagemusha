# disclosure-policy.md — 判断記録をどこまで公開するかの規則 / what gets published, and why not the rest

このディレクトリは、**走っているループの内側の記録**（判断台帳・価値判断モデル・人物像メモリ）から、
公開してよいものだけを**別工程で作り直したもの**だ。何を出し、何を出さず、**出さなかったことをどう数えるか**をここに固定する。

> **In English.** This directory publishes material derived from a live loop's private records — the
> decision journal, the distilled judgment model, the persona memory. This file fixes the four
> publication classes, the three tests that assign them, and the rule that the denominator is always
> stated. Nothing here is a template: it is one instance's ruling, written down so that an
> adversarial reader can check the arithmetic instead of trusting the selection.

---

## 1. 四つの公開区分 / the four classes

| 区分 | 意味 | このディレクトリでの現れ方 |
|---|---|---|
| **P0** | **原文公開。** 私用側の本文を、語彙置換だけ掛けて出す | `principles/public/` の21本・`failure-cases/case-00*.md` の3件 |
| **P1** | **派生公開。** 変換を掛けて出す。変換の**型**は明示するが、**削った中身は書かない** | `principles/derived/` の7本・`state-guardrails/`・`memory-architecture/` のスキーマ |
| **P2** | **存在と集計のみ。** 件数と分類は出す。中身は出さない | `failure-cases/aggregate-manifest.yaml` の非公開6件 |
| **P3** | **非公開。構造も示さない。** 題名も件名も出さない。理由は**広い分類だけ**を書く | `manifest.yaml` に `publication_class: P3` の行としてのみ存在 |

**P2 と P3 の差が要点だ。** P2 は「あることは言うが中身は言わない」、P3 は「**あることは数に含めるが、それが何についてかは言わない**」。
数に含めるのは、母数を偽らないため（§4）。題名を出さないのは、題名だけで内容が復元できる類だからだ。

## 2. 区分を決める三つの検査 / the three tests

### 検査1 — 本人可読性 (subject-readability)

**第三者が特定できるか**ではなく、**当事者本人が読んだら自分と分かるか・読んで嫌か**で切る。
匿名化は第三者に対しては効くが、**当事者に対しては効かない**——業種と時期と取引形態の組で、本人には必ず分かる。
この検査は後から足したものではなく、**このループが自分で焼いた検証器**であり、公開の設計中に自分でそれを破りかけて外部モデルに指摘された経緯がある（→ §5）。

> 判定: 当事者が読んで自分と分かり、かつ読んで嫌なら **P3**。分かるが害が無いなら P1 で変換して出す。

### 検査2 — 組合せ逆算 (combinatorial inference)

**単品で安全でも、公開セット全体を通読して手の内が逆算できるなら削る。**
通読の仕方を固定する——「**交渉相手がこのセットを読んだら、譲歩条件・焦り・信頼判定の予測精度が上がるか**」。
上がるなら、その部品は単品で無害でも落とす。

この検査は **P1 の書き方まで縛る**。派生版に「何を削ったか」の**中身**を書くと、穴の形から中身が復元される。
だから本ディレクトリの P1 ファイルは**変換の型**（下表）だけを書き、**削った内容の主題は書かない**。

| 型 | 何をする変換か |
|---|---|
| `T1` | 第三者が特定されうる発話 quote の**削除**（置換ではない） |
| `T2` | 金額・数量の削除 |
| `T3` | 事例の裏付け行（外部検証行）の削除 |
| `T4` | 出典の差し替え（残した1本で原則が自立することを確認したうえで） |
| `T5` | 手順・段取りに読める記述の削除 |
| `T6` | **quote の日付は月まで粗くする**——進行中の関係の当事者が、自分の受け取った文面と日付を突き合わせて自己特定できないように（出典タグから日を落とし、`[C:MM]` の形だけを残す） |

**T6 の射程は「原則ファイルの quote の出典タグ」だけ**だ。台帳エントリ ID（`D-YYYY-MM-DD-NN`）・原則の `adopted_at`・
実ログの時刻・`ledger_excerpt.md` が並べている 3 イベントの日付・
**`failure-cases/case-00*.md` の `occurred_at` と、そこに付いた quote の日付**は**対象外で、日単位のまま残している**
（誤断定の 3 件は「**当事者が存在しない**——自分の道具・自分の探索の失敗」を基準に選んだもので、
日付から自己特定しうる相手が居ない。→ [`failure-cases/README.md`](failure-cases/README.md)。
**免除は宣言する**——宣言されていない免除が検査の死に方だ、というのが §6 の作法だ）
——あれは「訂正 → 蒸留 → 差し替え」の順序そのものが証拠であり、粗くすると証拠が消えるからだ。
T6 が消しているのは**発話1本と日付の対応**であって、機構が動いた日付ではない。

⚠️ **置換で足りるときに削除を選んでいる箇所がある。** 匿名化しても毒が抜けない種類の記述（特定個人の属性・立場・能力への評価）は、
伏せ字にせず**行ごと落とす**。これは慎重さではなく、検査1の当然の帰結だ。

### 検査3 — 一方向エクスポート (one-way export)

**私用ログ → 公開版は、常に別工程の変換で作る。逆流させない。**

- 私用側（台帳・メモリ）は**読むだけ**。公開のために私用側を書き換えない
- 公開版は**新規ファイル**として書く。私用側の該当行は 1 文字も変わらない
- 公開版で言い回しが良くなっても、私用側へ戻さない

理由は品質ではなく**原料の保全**だ。**公開を意識して私用の判断記録を整えた瞬間、AI に焼く原料が劣化する**——
格好の悪い却下・言いよどみ・後で外れた仮説こそが蒸留の原料であり、それは「読まれるかもしれない」と思った瞬間に書かれなくなる。
だから公開版は**常に後から、別工程で**作る。

## 3. 迷ったときの決め方 / the tie-break

私用側のモデルには「迷ったら」という番号なしの決定規則がある。**誠実側・開示側・相手の負担が減る側に倒す。**
公開の判断ではこれが**そのままでは効かない**——開示側に倒すと、当事者の負担が増えることがあるからだ。
本ディレクトリではこう畳んだ:

> **開示側に倒す。ただし負担が第三者に向くときだけ、非開示側に倒す。**
> 自分に不利な事実（外した仮説・非ゼロ終了・記録の欠落）は**開示側**。
> 他人が読まれて困る事実は、匿名化の巧拙にかかわらず**非開示側**。
> **公開は不可逆なので、判定が割れたら P3 に倒す。**

この規則自体が、モデルの「迷ったら」を**この文脈へ適用した派生物**であって、原則の1本として別ファイルにはしていない（母数の数え方は §4）。

## 4. 母数を必ず書く / always state the denominator

選別して公開する以上、**選別工程そのものが証拠**だ。だから「何本中何本か」を必ず添える。
出さなかった数を書かない公開は、**都合のよい部分集合を全体に見せかける**行為と区別がつかない。

本パッケージの母数:

| 対象 | 母数 | P0 | P1 | P2 | P3 |
|---|---|---|---|---|---|
| 価値判断モデルの原則（安定 ID 付き） | **31** | 21 | 7 | 0 | **3** |
| 番号なし項目 | 2 | 0 | 1（状態ガードレールへ変換） | 0 | 0（1件は本ファイル §3 へ吸収） |
| 誤断定（自己申告の累積クラス） | **9** | 3 | 0 | **6** | 0 |
| 人物像メモリの実値 | — | 0 | 0 | 0 | 全件（スキーマのみ P1 公開） |
| 安定 ID を持たない非公開の構成物 | 2 | 0 | 0 | 0 | **2**（状態プロファイルの発火条件・人物像メモリの実値） |

⚠️ 最下行は `manifest.yaml` の `state-profile-triggers` と `persona-memory-values` の 2 行に対応する
（原則の 31 本にも「番号なし項目」の 2 件にも含まれない、**別の 2 つ**だ）。
**うち後者は上の「人物像メモリの実値」行と同じものを指す**——`manifest.yaml` 上の行数を合わせるための行なので、
**足し上げるときに二重に数えないこと**。

**P3 の 3 本については、番号（安定 ID）以外は何も書かない。** `manifest.yaml` に区分と広い理由分類だけが載る。
番号が飛んでいるのは意図的で、**飛びを隠すために番号を振り直すことはしない**（振り直せば母数が嘘になる）。

⚠️ **ただし、安定 ID は話題順に振られている。** だから欠番の位置から、非公開 3 本が
モデルのどのあたりの領域にあるかは**ある程度推測できる**——番号を残すことは、完全な遮蔽ではない。
それでも振り直さないのは、**母数の正直さを優先したから**だ。振り直せば位置は隠れるが、
「31 のうち 3 本を伏せた」という検算可能性そのものが消える。**どちらも取れないので、検算可能性を取った。**

⚠️ **節ごとの内訳表は出さない。** 内訳を出すと非公開分がどの領域に集中しているかが分かり、題名を伏せた意味が消える。
出すのは**全体の母数だけ**だ。これは検査2 の直接の帰結である。

## 5. この規則自体が訂正の産物である / the policy is itself a correction

最初の案は「状態プロファイルは出さない・誤断定は当事者を剥がして9件全部出す」だった。**両方とも外れている。**

- **出さなさすぎ**: 状態プロファイルを丸ごと落とすと、**証明価値を捨てすぎる**。運用語へ変換すれば、
  発火条件を1つも出さずに「その状態で何をしないか」だけを公開できる（→ `state-guardrails/`）
- **出しすぎ**: 「当事者を剥がせば9件出せる」は、**このループが自分で焼いた検査1（本人可読性）への自己違反**だった。
  匿名化しても当事者には分かる、と自分で書いておきながら、自分の記録に対しては適用していなかった

**自分の規律を、外部のモデルに思い出させられた。** 区分表・変換の型・母数の明記は、その訂正から出ている。
これを脚注ではなく本文に書いているのは、§3 の「自分に不利な事実は開示側」の実行である。

## 6. 語彙の置換 / vocabulary substitutions

公開版全体で、私用側の語彙を次へ置換している（`ledger_excerpt.md` の既存方針と同じ）。

- 承認者本人の呼称 → **承認者**／エージェントの内輪の呼称 → **サブエージェント**
- 取引先・案件の名前 → 削除（`[顧客]` 等の伏せ字を残す場合も、業種・時期は書かない）
- 金額・見積の数字 → 削除
- 個人・機械のパス、メールアドレス、非公開 URL、チャンネル識別子 → 削除
- **モデル名・CLI 名・プラン名 → 総称へ**（`[最上位モデル]` `[別ベンダーのモデル]` 等）。理由は秘匿ではなく**時変**——
  半年で古くなる固有名を原則の本文に埋めると、原則ごと古びる

**残したもの:** 実発話の quote（要約は台帳の規律違反）・件数・判断の骨格・**外した記録**。

⚠️ **quote の日付は「残したもの」から外した**（当初はここに「日付」と書いていた——**撤回する**）。
公開版の出典タグは `T6` で**月粒度**（`[C:MM]`）へ粗くしてある。日単位で残すと、
**進行中の関係の当事者が、自分の受け取った文面や打ち合わせの日と突き合わせて自己特定できる**
——検査1（本人可読性）が第三者ではなく当事者を見る、という定義の直接の帰結だ。
機構が動いた日付（台帳 ID・`adopted_at`・実ログの時刻）は上記のとおり日単位のまま残している。

### 宣言つきの例外 1 件 / one declared exception

[`failure-cases/case-002.md`](failure-cases/case-002.md) の承認者 quote には、**このキット自身の名（影武者）** が
エージェントの呼称として残っている。上の規則どおりなら「サブエージェント」へ置換するところだが、
**置換していない**——この語はリポジトリ名そのもので、構造的に公開されており、
かつ**訂正の刺さり方（「お前はその名前のはずだろう」）が置換で消える**からだ。

例外を**黙って作らず、ここに書く**のは `tests/forbidden_patterns.txt` の作法に倣っている
（あのファイルも、著者の公開ハンドルを許可する理由を本文に書いてから許可している）。
**免除は穴であり、宣言されていない穴が、検査の死に方だ。**

## 7. ID の体系について（読み間違い防止） / two ID systems, on purpose

- 本ディレクトリの原則ファイル名 `principle-NN.md` の `NN` は、**この実インスタンスの価値判断モデルが持つ安定 ID** だ
- キット同梱の [`../../../templates/judgment_model.md`](../../../templates/judgment_model.md) と
  [`../reference-instance/judgment/judgment_model.md`](../reference-instance/judgment/judgment_model.md) が使う `P1, P2, …` は**別の体系**（後者は書式を見せるための例示で、原則も例示）

同じ番号が別のものを指す。**引くときはどちらの体系かを明記すること**——これはこのインスタンス自身が
「表示番号で引くな・安定 ID で引け」という規約を焼いた理由と同じ穴だ。

## 8. 何を証明していて、何を証明していないか / scope

**証明している:**

- 判断原則が**選別されて**公開されていること、および**選別の規則が公開前に固定されている**こと
- 母数（31 / 9）と内訳が一致していること（`manifest.yaml` と各ディレクトリのファイル数で検算できる）
- 誤断定が**自己申告で累積カウントされている**こと、および**そのカウンタが公開分より大きい**こと

**証明していない:**

- 選別が正しいこと。**判定は 1 名の判断**であり、外部監査を受けていない
- 非公開 6 件・P3 3 本の中身が、公開分と同じ性質であること（読者は確かめられない。ここは**信用してもらうしかない部分**であり、
  だからこそ数だけは正直に出している）
- 匿名化に漏れが無いこと。**「検査した」は「無い」の証明ではない**——機械ゲート（`tests/forbidden_patterns.txt`）が拾うのは既知のパターンだけだ
- これがあなたの環境で妥当な線であること。**n=1・1インスタンス**の裁定である
- **公開しても手の内が漏れないこと。** 公開した原則の組合せは、**交渉相手の予測精度をある程度上げる**。
  検査2 は「上がるなら落とす」で個々の部品を切ったが、**残した 21 + 7 本の総体は依然として上げる**。
  これは消せていないコストであり、**裁定で織り込んだコスト**だ（証明価値と引き換えに払うと決めた）
