# ssot/ — 正本（いまの状態）

`decisions.md` / `tasks.md` / `glossary.md` / `people.md` は**上書き更新**の棚。
「いつそう決めたか」は追記専用の `judgment/decisions_journal.md` が持つ——
**状態と履歴は分ける**（混ぜると、最新を知るのに全部読む羽目になる）。
書式は各ファイル自身の見出しにある。

## 正本はプレーンなファイルだけ。CLI のメモリはキャッシュ

**このループの正本は、ここにある `.md` と、`judgment/` `approval_queue.md`
`verifiers.md` `system_map.md` `projects/*/charter.md` だけ**。それ以外——
Claude Code の自動メモリ、Codex の memories、対話の履歴、あなたの頭の中——は
**キャッシュ**であって正本ではない。

**判定は1つ。「そのキャッシュを今すぐ全部消して、ループは正しく回るか」**。
回るなら正しく置けている。回らないなら、そこに**しか**無い事実がある——
それは失われる場所に置かれた正本なので、ここへ移す。

なぜこの線を引くか。CLI のメモリは**その CLI のもの**で、他方からは見えず、
形式もパスもベンダーの都合で変わる。正本がそこに落ちた瞬間、ループは
「どの CLI で開いたか」に依存しはじめ、**開き直すたびに前提が変わる**。
プレーンファイルなら、Claude Code でも Codex でも、`grep` でも人間の目でも、
同じものが同じように読める。メモリは**それを速く思い出すための道具**であって、
思い出せなくなったら終わりという類のものではない。

## 2つの CLI を同じリポジトリで同時に動かすとき

**調停するのは git であって、私たちの気合いではない。**

- **上書き型の正本**（`ssot/*.md` `system_map.md` `verifiers.md`
  `projects/*/charter.md`）は、**同時に1セッションからだけ**触る。2つのセッションが
  同じ行を書き直すと、後から書いた方が黙って勝つ——衝突として見えない
- **追記型**（`judgment/decisions_journal.md` `approval_queue.md`
  `judgment/promotion_queue.md`）は**両方から同時でよい**。末尾に足すだけなので、
  ぶつかっても git の衝突として**目に見える**形で止まる
- 迷ったら追記側に寄せる。**見えない上書きより、見える衝突のほうが安い**
