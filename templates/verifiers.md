# verifiers — 常設検証器（standing verifiers）

> **検証器＝チェックリスト。** 業務ループの「検証器」は、コードの `assert` の代わり。
> 原理は3つ: **Done is a claim, not a proof（完了は主張であって証明ではない）／生成する側と採点する側を分ける／検証器に1ルール足すと以後の全出力に効く。**
>
> このファイルは2層でできている。**(A) 機械層**（正規表現・カレンダー計算・正本突合で自動判定できる層）と、**(B) 成果物タイプ別の DoD**（意味の判定を人間に残しつつ、抜け漏れを機械的に潰すパス）。

**大原則: 意味の正しさまで機械に判定させない。** 機械で判定できる層だけを機械に任せ、意味の判定は人間の仕事として残す。それでも体感ではエラーの過半がこの機械層で死ぬ。

---

## (A) 機械層 — 報告・送付の前に必ず通す

| 検証器 | 何を見るか | どう機械化するか |
|---|---|---|
| **表記・用語 lint** | 禁止表現・揺れる用語・崩れる記法 | `glossary.md` の「別名・表記ゆれ」列を正規表現で検出し、正式表記へ |
| **正本との突合** | 用語集・決定記録・過去成果物と矛盾していないか | 主張中の固有名詞を `people.md`/`glossary.md` と照合。未合致は `[要確認]` |
| **日付と曜日の検算** | 「7/30(金)」の曜日が本当に合っているか | 本文中の `日付(曜日)` を抽出しカレンダー計算で照合（人もAIも曜日を間違える） |
| **構造の整合** | 本文を直したのに目次・変更履歴・関連箇所が古いまま | 見出し⇔目次、合計⇔内訳、変更の波及先ファイルの棚卸し |
| **外部書き込みの読み戻し** | 書き込み API の「成功」応答と、実際に反映された内容のズレ | 外部サービス（ドキュメント・チケット・CMS 等）へ書いたら、成功応答を信用せず**読み戻して差分突合**してから「反映済み」と言う。部分適用を黙って成功と返す API は実在する（一致した箇所だけ適用し、外れた箇所を無言でスキップする置換系など）。書き込みと読み戻しはセットで1操作 |
| **未確認の断定**（否定に限らない） | 一次情報を見ずに断定している | 出力中の**断定**を検出する。否定（`無い/ありません/存在しない/見つからない/ゼロ件/初めて`）だけでなく、**帰属**（`〜のボール/〜待ち/〜が原因`）・**因果**・**数量**（`N分/N件/N回`）・**評価**（`壊れている/不要/地雷`）も対象。各ヒットに **それを支える一次情報を実際に見たか** を確認し、見ていなければ断定形を禁止して `[未確認]` を付すか、**先に1回叩いてから書き直す** |
| **否定命題の射程** | 「無い」と断定しているが、実際に見たのは一部だけ | 否定のヒットごとに **①どこを ②どこまで見たか** が併記されているか確認。**順序が要点**——先に射程を書くと、書けない時点で探索不足に自分で気づく。全量を見ていないなら「**X には無い（Y は未確認）**」へ整形する |

> **とくに危ない出所4つ**（未確認の断定は、たいていここから来る）:
> ① **既存のラベル** — 台帳や盤面の分類。**人が書いたものだけでなく、スクリプトが自動生成した文字列も含む**。ラベルの含意ではなく *そのラベルが実際に何を測ったか* を見る。とくに、現在値しか測っていないラベルを「変化した」と読むのは典型的な誤り。
> ② **サブエージェント・外部ツールの報告** — その射程の話であって、案件の射程ではない。
> ③ **自分が前に書いた文** — 見積もりとして書いた数字を、次のターンで実測として引くな。
> ④ **一般論からの外挿** — 「新しい方が正しいはず」の類。
>
> **索引・一覧 API の「無い」は、一覧では判定できない。** ファイル一覧・検索インデックス・キャッシュは、遅延も取りこぼしもする（同じフォルダを繰り返し照会しても中身が全部は返らない、という実測がある）。ID を直接指定して引くか、**本人の画面で確認する**。
>
> **訂正は、訂正される側より強い証拠で支えろ。** 逆向きに言い換えるのは訂正ではない。「X は間違い」と「したがって非 X が正しい」の間には、独立した証拠が要る。訂正の勢いで射程外まで書くのは、最初の誤りより印象が悪い。

## (B) 成果物タイプ別 DoD — 該当タイプは、報告・送付前にこのパスを1周

> 出典: 実運用で「口頭で毎回同じ指摘をさせられていた」ものを検証器に変換した標準。
> 使い方: 作った成果物のタイプを見て、対応する行の DoD を1周する。指摘があれば直してもう1周。

1. **要件定義・仕様設計**
   → 独立視点の抜け漏れ監査を1周（別セッション、または自分で帽子を替えて）。状態機械があるなら全状態×全遷移、アクターがいるなら全アクター網羅を機械的に確認。

2. **機能・UI設計**
   → DoD ＝ 全アクター × 端から端の動線（入口→操作→完了→事後状態の表示まで）＋ 通知マトリクス（誰に・いつ・何を）＋ 異常系（失敗・取り消し・権限なし）。

3. **対外文書・対外的主張**（提案書・メール・チャット・記事）
   → ① 事実の裏取りパス（数値・制度・URL は出典確認、無ければ書かない）② 受け手ロールプレイ1周（読者の目で通読し、詰まる箇所・誤読・反論を潰す）。
   → ③ **「送ります」と書いたものは、その瞬間に約束台帳入り。** 対外文書の中の約束（次に送る成果物・次にやる調査・報告するタイミング）を抽出して、タスク側に1件立てる。**次の対外便を組むたびに、未履行の約束を先に棚卸しする**——約束が送信箱の中にしか無いと、盤面の「手つかず」欄に落ちたまま相手だけが待つ。
   → ④ **配送前チェック**（送信ボタンの直前に3つ）: **未履行の約束は無いか** ／ **添付・リンクは実物が開くか** ／ **前便で相手が投げてきた問いに全部答えたか**。

4. **HTML・ビジュアル成果物**
   → 実レンダリング検証（ヘッドレスでスマホ幅＋PC幅を撮って目視）してから納品。grep だけで「崩れてない」と言わない。

5. **差し替え・改訂**
   → 整合チェック（タイトル⇔中身、合計金額⇔内訳、目次⇔本文、変更が波及すべき同期先ファイルの棚卸し）。
   → **「棚卸し」は具体名で固定する**（忘れるのはここ）。改訂したファイルごとに同期先を列挙して書き出しておく——検証器を直したらそれを引用しているチェックリスト類、判断モデルを直したら解説文書とひな型、といった具合に。
   → **正本の位置や適用軸を変えたら、それを典拠にしている文書を全部追う。** 古い典拠を指したままの案件憲章・スクリプト・スキルが、変えたはずの規律を静かに生かし続ける。**改訂したターンで同期の要否を判定し、要るなら同期タスクを積むまでが完了条件。**

6. **チャット・メッセージ投稿**
   → lint: 宛先メンション必須・依頼には期限とアクションを明記。
   → **リンクを送るときは、受信者側の閲覧権限まで確認する。** 送信ダイアログを通っても、共有ストレージの権限付与は別物で、付与漏れは普通に起きる。**権限 API の表示には遅延と射程の限界がある**ので、疑わしければ共有画面の目視を一次情報とする。

7. **切り貼り・機械編集**（sed / 置換系）
   → 編集後に構造プローブ（キー要素の存在確認）。アンカー文字列が本文中に再出現しうる場合は、置換前に一意性を検証（同じ文字列が複数箇所にあると誤爆する）。

## 停止規則

- 監査1周で指摘ゼロ → 報告・キュー投入。
- 指摘あり → 直してもう1周。**最大2周**。それでも収束しなければ人間へ（迷いとして承認キューの「迷い」欄に書く）。
- **夜間は回さない。** 自律実行の成果物は人間が読む速度を簡単に超える。読まれない成果物が積み上がるのは、売れない在庫が積み上がるのと同じ。

## 検証器の育て方（却下の蒸留）

このファイルは書いて終わりではなく、**却下から育てる**。

1. 承認キューで却下・修正が出たら、その理由を `decisions.md` に1件記す。
2. 週次でそれらを読み返し、**同じ穴が2回開いたら検証器を1本足す**（機械層に落とせるなら (A) へ、判断が要るなら (B) の DoD へ）。
3. 足した検証器は以後の全出力に効く。人間が同じ指摘を三度することは無くなる。
4. **ただし「検証器を足した」は「穴が塞がった」ではない。** 機械層に1行あるのに同じクラスの事故が再発する、は普通に起きる——**書いてあること**と**出力の直前に必ず通ること**は別だからだ。同じクラスが再発したら、次に問うのは「文言を強めるか」ではなく「**この検証器は、いつ・何によって強制的に実行されるのか**」。塞ぐ手は文言の追加ではなく、実行タイミングの設計にある。

> **足すときに、いつ発火するかを事前に決めておく。** 「3回目が出たら文言でなく強制実行の設計に移る」のように**閾値を先にコミット**しておくと、再発を数えるだけで自動的に次の一手が決まる（決めていないと、同じ指摘のたびに文言だけが伸びていく）。
