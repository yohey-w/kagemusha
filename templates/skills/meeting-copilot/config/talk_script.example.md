# 台本の最小例（架空の案件）

この形式を守ると、viewer2.py が中段のテレプロンプターとして読める。

書式の規則（parse_script が見ているもの）:

| 行の形 | 画面での出方 |
|---|---|
| `## 【N】 見出し` | 段N の始まり。N は段取りJSONの並び順(1始まり)と対応 |
| `**声に出す文**` | 大きく表示（読み上げる文）。後ろに続く文字は小さい注記になる |
| `### 小見出し` | 段の中の区切り |
| `▸ 条件 → 言うこと` | 折りたたまれた分岐。開くと「言うこと」が大きく出る |
| `（ト書き）` | 小さく薄い注記 |
| 表 | 小さく薄い覚え書き |

`▸` 行の「」で囲んだ部分は、番人が「台本が想定している言い回し」として拾う。
相手がその言い方をしたら、疑問符が無くても第2層(answerer)を呼んでよい、の判定材料になる。

`## 【N】` 以外の `##` 節はテレプロンプターに出ない。準備メモはそちらへ書く。

---

## 【1】 現状の確認

**まず、いまの運用を確認させてください。**

### 聞く順番

**いまの在庫の管理は、どなたが担当されていますか。** （人数まで聞く）

**データは、何年分くらい残っていますか。** （移行範囲の見積りに効く）

▸ 「担当は一人」と返ってきたら → 「その方が抜けたときの手当ては、いまどうされていますか」

▸ 「わからない」と言われたら → 「では、いまの置き方で仮に作っておきます。あとから差し替えられます」

（相手に喋らせる段。こちらの案はまだ出さない）

---

## 【2】 移行範囲の確定

**ここからは、移行の範囲を決めさせてください。**

**本番のデータだけを移す形で、いったん置かせてください。**  検証環境は含めない

▸ 「検証環境も」と言われたら → 「できます。次の弾でお見積りしますね。まずは本番だけで間に合わせます」

▸ 「画面も直せますか」と言われたら → 「できます。ただ今回の範囲の外なので、お見積りしてご連絡します」

**このあと、社内ではどなたの承認が要りますか。**

---

## 【3】 次回までの宿題

**最後に、決まったことを読み上げさせてください。**

（ここで復唱する。復唱しないと「合意した」が双方でずれる）

**次にお話しするのは、いつがよろしいですか。**
