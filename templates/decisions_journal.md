# decisions_journal — 判断台帳（L2・追記専用イベントログ）

> **判断蒸留の材料（L2）。** 裁定・訂正・却下・温度を、起きたそばから1件書く。
> `decisions.md`（SSOT）とは別物: あちらは「いま何が有効か」、こちらは「どう判断する人か」。
> 主な読者はエージェントと週次蒸留。ID・topic・マーカーの書式を崩さないこと（正規表現で引かれる）。
> 詳しくは [`../docs/judgment-distillation.md`](../docs/judgment-distillation.md)。

**4つの規律**

1. **追記専用・上書き禁止。** 間違った記帳は消さず、`revises: D-...` を付けた新エントリで訂正する（イベントソーシング）。
2. **verbatim（実発話）を残す。** `quote:` は承認者の原文をコピペで。要約しない。原則に昇格してよいのは quote が引けるものだけ。
3. **推論は昇格させない。** 「たぶんこう考えている」は `principle: [working hypothesis]` タグで台帳に留め、価値判断モデルには上げない。承認者の一言で昇格する。
4. **理由は現場で採取する。** 承認者が理由を言わなければ、差分から `なぜ(仮説):` を推定し、`検証:` 欄に「何が起きたら当たり/外れが確定するか」を書く。事実からあとで理由を導出することはできない（過小決定）ので、判断が起きたそのターンで採取する（→ [現場採取の原理](../docs/judgment-distillation.md)）。

**記帳判定器（1つでも Yes なら記帳）:** ①裁定した ②エージェントを曲げた（却下・訂正=最優先）③金額・締切・対外送信・温度 ④一般則の教訓 ⑤迷い・保留 ⑥前提の重み変化 ⑦委任境界の移動 ⑧待機中の仮説・予測への答え合わせに該当。取らない: 選択肢の無い作業指示・進捗確認・雑談。

書式: 見出し1行で意味が取れること（`grep '^## D-'` で判断一覧が出る）。必須は「判断」「状態」の2行のみ。裁定・訂正なら `quote` と `principle` も付ける。3行で書けるときは3行でよい（記帳コスト最優先）。

- quote: 「なんか硬い。そうじゃない」
- なぜ(仮説): 宛先は付き合いの長い相手。過去に承認された同宛先メール（D-2026-06-… 参照）は短文・一人称だった → 硬い敬語の定型文が関係性に合っていない、が最良説明。対抗仮説として「長すぎる（情報過多）」も併記
- 検証: 反復型。次に同じ宛先へ出す下書きを「短め・砕けたトーン」で先出しし、無修正で通れば仮説強化、再訂正なら棄却して新仮説（`revises:`）。※何度通っても原則には上げない——昇格は承認者が明示確認したときだけ
- principle: [working hypothesis]（宛先の関係性でトーンを変える、はまだ実発話 quote が無い）
- 状態: 観測記録
