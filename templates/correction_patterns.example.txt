# correction_patterns.example.txt — a MENU, not a default.
#
# Copy this somewhere in your own data (e.g. judgment/correction_patterns.txt,
# outside the kit) and cut it down to the phrases YOU actually use when you
# overrule an agent. scripts/correction_scan.py has no built-in list and will
# refuse to run without --patterns, on purpose: the vocabulary of your
# corrections is the one part of this that cannot be shipped. A list baked into
# the script would quietly become everyone's, and then every user's material
# file would be shaped by phrases they never say.
#
# FORMAT: one Python regex per line, matched case-insensitively against your
# side of the transcript. Blank lines and lines starting with '#' are ignored.
# An empty file is an error (an empty list harvests nothing and looks exactly
# like a quiet week).
#
# TUNING, in one rule: start broad, narrow later. A pattern that is too broad
# costs you one line to skim in a review. A pattern that is too narrow costs you
# the signal entirely, silently, and you will never know what you missed. The
# review step downstream throws out false hits by design — over-collection is
# cheap here and under-collection is not.
#
# Aim at VOCABULARY, not meaning. "The user disagreed" is not a regex; "that's
# not what I asked" is. If a discipline of yours is worth auditing, the words
# you use when it gets broken are usually the same three or four every time.

\bno,|\bnot what i\b|that'?s not\b|\bnot like that\b
